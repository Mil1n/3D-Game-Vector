# VECTOR//NULL

**VECTOR//NULL** — законченный браузерный vertical slice быстрого sci-fi FPS с roguelite-улучшениями и тремя перестраивающимися аренами. Один прогон занимает примерно 5–8 минут: выберите полигон, активируйте фазовый узел, выполните динамическую задачу, переживите Сдвиг реальности, победите Стража Разлома и удержите канал эвакуации.

Проект не загружает внешние модели, текстуры или аудиофайлы. Арена, оружие, противники и VFX построены из оптимизированной процедурной геометрии, а звук синтезируется через Web Audio API. Это делает сборку воспроизводимой и исключает битые ссылки на ассеты.

## Основная механика

Сдвиг реальности заранее предупреждает игрока, затем безопасно меняет маршруты арены и включает один понятный модификатор: пониженную гравитацию, кинетическое ускорение, энергетический шторм или комнату снабжения. После Сдвига игрок выбирает одно из трёх временных улучшений. Система не создаёт геометрию поверх игрока и не наносит внезапный неизбежный урон.

## Карты

Карта выбирается в главном меню перед стартом забега. Все три полигона используют общий игровой цикл, но отличаются геометрией, высотами, линиями огня, точками появления и безопасными маршрутами во время Сдвига:

- **Нулевая решётка** (`null-grid`) — симметричный трёхкольцевой фазовый комплекс со сбалансированными дистанциями;
- **Затонувший ретранслятор** (`sunken-relay`) — прямоугольный грузовой двор с длинными прострелами и тесными контейнерными проходами;
- **Небесная литейная** (`sky-foundry`) — вертикальная литейная башня с пятью лучами, тремя уровнями и открытыми позициями.

## Технологии

- HTML5, CSS3 и нативные ES-модули;
- Three.js / WebGL;
- cannon-es с фиксированным физическим шагом;
- Web Audio API с отдельными шинами Master, Music, Weapons, Effects, Environment и UI;
- IndexedDB для профиля и статистики, localStorage для ранней загрузки настроек;
- Vite для разработки и production-сборки;
- встроенный `node:test` для быстрых проверок конфигураций и автомата состояний.

## Требования

- Node.js 20.19 или новее;
- npm 10+ или pnpm 10+;
- современный браузер с WebGL 2, IndexedDB и Web Audio; Pointer Lock желателен, но предусмотрен drag-to-look fallback;
- клавиатура и мышь. Сенсорное управление в этом vertical slice не предусмотрено.

## Установка и запуск

```bash
npm install
npm run dev
```

Откройте адрес, который напечатает Vite (по умолчанию `http://127.0.0.1:5173`). Не запускайте `index.html` двойным кликом: ES-модулям нужен локальный HTTP-сервер.

Эквивалент с pnpm:

```bash
pnpm install
pnpm dev
```

## Production-сборка

```bash
npm run build
npm run preview
```

Готовые файлы создаются в `dist/`. Параметр `base: './'` позволяет разместить сборку не только в корне домена.

## Управление

| Действие | Клавиша |
|---|---|
| Движение | `W A S D` |
| Обзор | мышь |
| Прыжок | `Space` |
| Спринт | `Shift` |
| Приседание / скольжение | `C` / `Ctrl` |
| Энергетический рывок | `Q` |
| Стрельба | левая кнопка мыши |
| Прицеливание | правая кнопка мыши |
| Перезарядка | `R` |
| Взаимодействие | `E` |
| Оружие | `1`—`5` или колесо мыши |
| Пауза | `Esc` |
| Debug Mode | `F3` |

Pointer Lock активируется после нажатия кнопки старта или продолжения. Если API недоступен (например, во встроенном браузере), canvas получает фокус: клавиатура продолжает работать, а для обзора нужно зажать кнопку мыши и тянуть курсор. Повторный клик по игре снова пробует включить Pointer Lock; `Esc` открывает паузу.

## Оружие

- **VX-9 «Импульс»** — автоматический импульсный карабин средней дистанции с управляемой вертикальной отдачей.
- **SG-4 «Осколок»** — близкобойный кинетический рассеиватель с отдельным raycast каждой дробинки и сильным падением урона.
- **ARX «Нуль-копьё»** — медленная высокоточная энергетическая винтовка с мощным трассером.
- **PX-7 «Поток»** — мобильный плазменный автомат с очень высоким темпом огня и яркими импульсами для ближней дистанции.
- **HMX-1 «Сверхнова»** — тяжёлая имплозионная пушка: медленный заряд детонирует в точке попадания и поражает группу целей.

Каждое оружие имеет отдельные урон, темп, магазин, резерв, перезарядку, разброс в движении и ADS, отдачу камеры и модели, дальность, falloff, звук и цвет VFX. Для PX-7 и HMX-1 синтезируются собственные многослойные звуковые профили: короткий высокочастотный плазменный импульс и тяжёлый низкочастотный имплозионный выстрел. Raycast сначала проверяет геометрию мира, поэтому урон не проходит сквозь препятствия.

## Противники

- **Штурмовик** удерживает среднюю дистанцию, меняет позиции, отступает и стреляет телеграфированными очередями.
- **Охотник** использует фланги и быстрый ближний бой, вынуждая менять позицию.
- **Страж Разлома** — элитный многофазный противник со щитом, веером энергетических сфер и заранее обозначенными опасными зонами.

ИИ использует конечный автомат, поле зрения, line-of-sight, реакцию на выстрелы, память последней позиции и ограниченный поиск. Система токенов ограничивает число одновременно атакующих обычных врагов. Точки появления выбираются вне прямой видимости игрока.

## Архитектура

Игровые системы не изменяют DOM друг друга напрямую. Они публикуют события через `EventBus`; `UIManager` отображает полученные данные, а `Game` контролирует жизненный цикл. Ввод преобразуется в action-состояния через `InputManager`, а физика работает фиксированными шагами независимо от частоты рендера. Match-time таймеры обновляются только игровым циклом, поэтому пауза, Upgrade Selection и потеря фокуса не оставляют фоновых таймеров.

Основные состояния: `Boot`, `Loading`, `MainMenu`, `Tutorial`, `Playing`, `Paused`, `UpgradeSelection`, `Victory`, `Defeat`. Недопустимые переходы отклоняются автоматом состояний.

Слой состояния/событий отделён от Three.js-представления. Это сохраняет возможность позднее вынести авторитетную симуляцию в Node.js/Colyseus, добавить snapshots, interpolation и reconciliation без переписывания интерфейса.

## Как добавить оружие

1. Добавьте полный объект в `src/configs/weaponConfigs.js`: id, название, тип, урон, fire rate, магазин/резерв, reload, spread/ADS/move spread, recoil, range/falloff и цвет.
2. Добавьте id в `WEAPON_ORDER`.
3. Добавьте выразительную процедурную форму в `createWeaponModel()` файла `src/combat/WeaponSystem.js`.
4. При новом принципе выстрела расширьте `tryFire()`/`traceShot()`, сохранив проверку ближайшего world-hit.
5. Запустите `npm test`, затем проверьте стрельбу, смену во время reload и рестарт матча.

## Как добавить противника

1. Добавьте data-driven конфигурацию в `src/configs/enemyConfigs.js`.
2. Добавьте его читаемый силуэт в `makeEnemyVisual()`.
3. Реализуйте отдельную функцию принятия решений в `EnemySystem`, используя общие perception, navigation, attack token и projectile/hazard pools.
4. Добавьте выбор нового типа в `RunDirector.updateSpawning()` и проверьте safe spawn/LOS.

## Как добавить улучшение

Добавьте запись в `src/configs/upgradeConfigs.js` с уникальным `id`, редкостью, лимитом стаков и объектом `effects`. Поддерживаемые эффекты централизованно применяет `UpgradeSystem.applyEffects()`. Новый вид эффекта следует реализовать там и в системе-получателе; UI автоматически показывает название, описание и редкость.

## Как добавить динамическое событие

1. Опишите модификатор в `ANOMALIES` файла `src/systems/RunDirector.js`.
2. Добавьте безопасную визуальную перестройку в `Arena.beginShift()` и `Arena.applyShift()`.
3. Примените gameplay-модификатор через `RunDirector.setAnomaly()`.
4. Проверьте предупреждение, паузу во время предупреждения, безопасность позиции игрока и восстановление после рестарта.

## Добавление или изменение карты

Карты описаны data-driven конфигурациями в `src/configs/mapConfigs.js` и собираются в `Arena.build()` из переиспользуемых материалов и геометрий. Новый полигон должен получить уникальный id и запись в каталоге выбора главного меню. Каждый новый сектор должен иметь:

- статический cannon-es коллайдер;
- читаемый цвет/номер и не менее двух выходов;
- waypoint или связь с существующим графом;
- валидную точку появления вне геометрии;
- корректный world raycast;
- безопасное состояние до и после Сдвига.

После изменения обязательно проверьте три кольцевых маршрута, точки задач и возможность вернуться в центральный сектор.

## Настройки графики и доступности

Настройки сохраняются и применяются без фиктивных кнопок: яркость сцены, качество/DPR, тени, дальность, частицы, FOV, FPS cap, громкости шин, чувствительность, инверсия Y, hold/toggle ADS и crouch, UI scale, head bob, camera shake, flash intensity, контраст и цвет прицела. Fullscreen запрашивается только из пользовательского жеста. Motion blur по умолчанию отсутствует.

Часть тяжёлых эффектов намеренно не включена: SSAO и настоящий motion blur дали бы непропорциональную стоимость для браузерного vertical slice. В меню они не выдаются за активные функции.

## Сохранения

`SaveManager` хранит версионированный профиль в IndexedDB: статистику, опыт, рекорд, достижения, открытые косметические варианты, факт обучения и дату запуска. Формат проходит валидацию/миграцию. При повреждении создаётся безопасная резервная запись и загружаются значения по умолчанию. Малый snapshot настроек хранится в localStorage, чтобы FOV/DPR/громкость были доступны до открытия базы.

Удаление прогресса доступно из настроек и требует явного подтверждения.

## Debug Mode

`F3` открывает отдельную диагностическую панель: FPS/frame time, draw calls/triangles, объекты, активные враги и частицы, позиция/скорость/состояние игрока, ближайший AI state, фаза директора, аномалия и доступная оценка памяти.

Команды панели позволяют включить бессмертие/бесконечные патроны, создать врага, уничтожить врагов, остановить ИИ, принудительно запустить Сдвиг, завершить задачу и перезапустить матч. Визуальные переключатели показывают доступные collision/spawn/objective/navigation данные арены.

## Проверка

```bash
npm test
npm run build
npm run preview
```

Ручной smoke-check:

1. Старт → Pointer Lock или drag-to-look fallback → движение, прыжок, спринт, crouch/slide/dash.
2. Стрельба каждым оружием, ADS, пустой магазин, reload и смена во время reload.
3. Пауза через Esc, изменение громкости/FOV, возврат и повторный Pointer Lock.
4. Выполнение задачи, выбор улучшения, Сдвиг, элитный противник и эвакуация.
5. Рестарт из паузы и с экрана результата; старые враги/VFX/снаряды должны исчезнуть.
6. Потеря фокуса, resize, fullscreen и F3.

## Известные ограничения vertical slice

- Только одиночный режим; сетевой транспорт, лобби и матчмейкинг намеренно отсутствуют.
- Навигация использует небольшой граф путевых точек и локальное обходное steering, а не тяжёлый runtime-navmesh.
- Процедурный звук выразителен и вариативен, но не заменяет финальный студийный sound pass.
- Поддерживается desktop keyboard/mouse; контроллер и мобильный ввод оставлены для следующего этапа.
- Настоящие SSAO, motion blur и texture streaming не используются ради стабильной производительности на интегрированной графике.
